# AHT10 ESP8266 Sensor

## Projekt-Übersicht

Sensor-Node auf Basis ESP8266 mit AHT10 für Temperatur- und Luftfeuchtigkeitsmessung. Stellt einen Webserver bereit und hat einen WLAN-Hotspot als Fallback.

## Hardware

### Komponenten
- **ESP8266** (NodeMCU v2)
- **AHT10** Temperatur- und Feuchtigkeitssensor (I2C)
  - Temperatur: -40 bis +85 °C, ±0,3 °C
  - Luftfeuchtigkeit: 0–100 % rH, ±2 %

### Verkabelung

```
AHT10       NodeMCU
├─ VCC  →   3.3V
├─ GND  →   GND
├─ SDA  →   D2 (GPIO4)
└─ SCL  →   D1 (GPIO5)
```

**I2C-Adresse:** 0x38

## Software

### ESPHome Configuration

**Datei:** `aht10-esp8266.yaml`

#### Wichtige Parameter

- **I2C:** SDA=GPIO4, SCL=GPIO5
- **AHT10 Update-Rate:** 30s
- **Uptime Update:** 60s
- **Web Server:** Version 2 (nicht Version 3 — SSE-Bug in ESPHome 2026.1.0, siehe hlk-ld2450-esp32.md)
- **WLAN Hotspot:** "AHT10 Sensor Hotspot", Passwort `esphome123`
- **Captive Portal:** aktiv

#### Board-Varianten

| Board | YAML-Wert |
|-------|-----------|
| NodeMCU v2 | `nodemcuv2` |
| Wemos D1 Mini | `d1_mini` |
| ESP-01 | `esp01_1m` |

## Funktionsweise

1. ESP8266 verbindet sich mit WLAN
2. AHT10 liefert alle 30s Temperatur und Luftfeuchtigkeit
3. Werte sind über Web-UI (`http://ESP_IP`) und Home Assistant (API) abrufbar
4. Bei WLAN-Ausfall: Hotspot "AHT10 Sensor Hotspot" wird aufgespannt
5. Nach 15 Minuten ohne WLAN: automatischer Neustart

## Debugging

### Crash-Diagnose

**"Letzter Reset-Grund"** in der Web-UI:

| Wert | Bedeutung |
|------|-----------|
| Power On | Normaler Start |
| External System | Reset über EN/RST-Pin |
| Software/System restart | OTA oder API-Neustart |
| Software Watchdog reset | Software hat zu lange geblockt |
| Hardware Watchdog reset | Schwerwiegender Hänger |

### Flashen (USB, erstmalig)

```bash
docker run --rm -v /home/schorsch/esphome/config:/config --device=/dev/ttyUSB0 esphome/esphome upload /config/aht10-esp8266.yaml --device /dev/ttyUSB0
```

### OTA-Flash

```bash
docker exec esphome esphome upload /config/aht10-esp8266.yaml --device <ESP_IP>
```
